# HR Policy Request Management — Synthetic Reference Solution

## What is included
- 500 employees, 8 departments, 5 request categories
- 150 policy documents, 300 policy versions, 150 knowledge articles
- 5,000 tickets, exactly 20,000 messages, assignment and SLA records
- Ticket lifecycle events, message-to-policy citation bridge, resolutions
- Separate `ground_truth.csv` / `ground_truth.json` for seeded anomalies and context labels
- CSV, JSON and SQLite-compatible SQL seed script
- Data dictionary, metrics, validation summary and source manifest

## Run / inspect
- CSV: open each `*.csv` file with Excel, LibreOffice or pandas.
- JSON: each `*.json` file contains a JSON array (except summaries).
- SQL: execute `seed.sql` with SQLite (`sqlite3 hr.db < seed.sql`).
- Generator entry point: `python generate_data.py --seed 20261022 --tickets 5000 --out output`
  The included canonical full-scale data files were generated by the deterministic reference generation process using the same seed. The compact entry point demonstrates scale parameter handling and writes a ticket-scale sample; it is not a full independent regeneration of every entity. `reproducibility_check.json` documents the exact checksum method and this limitation.

## Routing rules
1. Employee Relations / sensitive cases -> `HR-Employee-Relations` restricted queue.
2. Otherwise route by category default queue.
3. Ambiguous or missing-context requests -> ask a targeted clarification before a definitive answer.
4. Policy answers must cite a policy version effective on the ticket date and within the employee's audience.
5. Never assert approval or eligibility unless an effective, approved policy supports the claim.

## SLA rules
Business calendar: Monday-Friday, 09:00-17:00 local business time. Target hours come from Category. SLA due dates are derived by adding target business hours to ticket creation time. Weekends and non-business hours are excluded. SLA status is derived from due time and resolution time.

## Known seeded defects
See `ground_truth.csv` only during evaluation. Four required defects are intentionally present:
- obsolete policy citation
- sensitive case assigned to general queue
- SLA calculated with elapsed rather than business hours
- unsupported policy claim
Additional ambiguity and missing-context labels are included.

## Data model and cardinality
- Department 1:N Employee; Employee 1:N Ticket.
- Category 1:N PolicyDocument and 1:N Ticket.
- PolicyDocument 1:N PolicyVersion and 1:N KnowledgeArticle.
- PolicyVersion 1:N MessagePolicyCitation; Message 1:N MessagePolicyCitation (bridge).
- Ticket 1:N Message, Assignment, TicketEvent; Ticket 1:1 SLA; Ticket 1:0..1 Resolution.
- Ticket -> Employee/Department/Category/PolicyDocument are mandatory; manager, message sender, resolution version are optional.
- Event history is append-only in `TicketEvent`; assignment history is represented by `Assignment`.

## Privacy and provenance
All names, emails, IDs and events are synthetic. Email domain `.test` is reserved for testing. No external personal data or licensed datasets were used. No production policy text is represented; policy summaries are synthetic schema examples only.

## Reproducibility
Seed: `20261022`. See `validation_summary.json` for row counts and checks. Checksums for canonical outputs are in `source_manifest.json`. The current reproducibility check confirms deterministic serialization; a full independent second run of the complete generator remains a follow-up validation step.

## Run the interactive application
The project now also includes a local Streamlit demonstration app.

```powershell
py -m pip install -r requirements.txt
py -m streamlit run app.py
```

Open the local URL shown in the terminal (normally `http://localhost:8501`). The app provides a dashboard, request submission, automatic routing of sensitive requests to Employee Relations, business-hours SLA due dates, request tracking, policy library search, and integrity checks. It uses `hr.db` if present; otherwise it initializes the database from `seed.sql`.

**Important:** this is a local synthetic-data prototype, not a production HR platform. It does not include login/role-based access control, email notifications, approval integrations, or a secure production hosting setup. Do not enter real employee or confidential information.
